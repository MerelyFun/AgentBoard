# AgentBoard 办公室 V2 美术方向

本版按用户对上一版的反馈重做。V2 三张资产已完成技术检查、浏览器原生尺度集成和独立视觉审查，批准范围是办公室资产及其页面呈现。本文记录方向、来源和验收证据；旧 `office-concept.png`、`office-backdrop.webp`、`office-workers.webp` 不再是 V2 样板。制作与检查采用 `create-game-assets` 的方向、规格、来源及上下文检验方法。

## 使用场景与技术框架

- 产品：React + Vite + TypeScript 的 AgentBoard 网页，呈现真实执行的办公室状态；不是新的游戏项目，也不引入游戏引擎。
- 主要操作：选项目、按岗位/状态筛选、观察最近上报、点人物或列表进入详情。岗位与执行状态来自数据，图像不存任务、阶段、数量或其他业务文字。
- 桌面默认单排主场景以 **460–520 CSS px** 为目标，当前 CSS 最小高度 460 px（视窗宽 1600 px 起为 470 px）；三项目共用一个连续房间，每项目至少一个共享桌岛、每桌最多四个 run。超出时复用模块增加桌岛，让内容自然增高，避免截断执行。
- 手机可选择项目，展示所选项目的桌岛和人物；保持桌与人物可辨识的图形尺度，调整取景与布局，不把完整三岛总览缩成微型画面。
- 场景常驻文字只有简短岗位与状态小胶囊。任务、大小阶段、摘要、时间、证据和实例编号放详情或下方列表，不在工位周围堆叠长标签。
- 真实模式只有存在于当前有效筛选结果中的真实 run 才有人；无 run 保留无人房间和空桌，不填示意员工，不以画面证明进程此刻仍在执行。一个 run 不重复画成人物；席位不足时增加桌岛，并保留完整列表，不伪造或丢失执行数据。

## 视觉系统

| 维度 | V2 约定 |
| --- | --- |
| 页面底色 | 白色侧栏 `#FFFFFF`，暖白画布 `#FAF8F3`；场景与白色控件有轻微明度差，不使用大面积深绿侧栏 |
| 强调色 | 青绿 `#169C8E`，用于当前选择、主操作和少量装饰；浅青绿 `#DFF2EC` 用于选中底色 |
| 文字与分隔 | 深灰绿 `#253739`，次级文字 `#6F7D79`，柔和分隔 `#E6EAE4`；功能文字由 HTML/CSS 绘制 |
| 环境色 | 浅木 `#CBB28F`、奶油 `#EEE7D8`、低饱和叶绿 `#7D9C82`；环境装饰退后，人物与工位轮廓优先 |
| 状态色 | 原生胶囊可用青绿、琥珀与柔和红表达状态，同时提供文字/图标；不得仅用人物衣服颜色表示运行状态 |
| 形状 | 柔和卡通，圆角家具、简化大形、清楚的头身与坐姿；避免尖锐写实几何、密集纹理和过多小摆件 |
| 摄影机 | 正交等距/一致的高位三分之四视角；平行边保持平行，三个桌岛与两朝向人物共用同一地面轴向与俯角，无广角透视漂移 |
| 明度 | 房间保持低对比、宽松留白；桌岛为中间层，人物轮廓与原生胶囊为焦点，缩到实际显示尺寸仍能辨识坐姿与桌边关系 |
| 材质与边缘 | 哑光木材、布料与柔和屏幕，轻微圆润体积感；整套采用一致的干净边缘和接触阴影，不混合像素描边与写实贴图 |
| 光照 | 统一左上方柔光、低对比阴影；桌与人物不各自生成完整地板或大块落地阴影，避免叠层后出现双重光照 |
| 细节 | 只保留在原生尺寸能读出的电脑、头发、衣着和椅子轮廓；不靠放大才可见的细节建立身份 |
| 动态 | 轻微呼吸/状态变化即可；支持减少动态效果。没有需要运行的真实状态时保持静态，不用不停跳动暗示正在执行 |

以上色值是实现用的方向色板，不宣称生成图片已经精确符合；以同一参考图约束资产家族，再在原生尺寸合成检查。

## 分层与资产家族

运行时已导出三张图片，具体记录见 [asset-manifest-v2.json](asset-manifest-v2.json)。原始 PNG 保留在已忽略的 `.local/office-v2-source-art/`，manifest 记录各源稿完整路径；本任务核对了源稿文件名，PNG 与 WebP 的逐像素 alpha 比较由 root 完成。导出仅使用 Pillow WebP 编码（quality 88、method 6），不裁切、不缩放。

| 资产 | 运行路径 | 必须包含 | 必须排除 |
| --- | --- | --- | --- |
| 无人房间 | `src/assets/studio-room-v2.webp` | 连贯暖白/浅木办公室、少量窗/植物、三岛布局可用的空地 | 人、椅子、桌岛、业务文字与界面框 |
| 共享桌模块 | `src/assets/studio-desk-v2.webp` | 一张可复用共享桌、四台电脑、清楚的四侧坐席对接位置 | 人物、椅子、地板、墙面、项目名和标签 |
| 坐姿人物图集 | `src/assets/studio-people-v2.webp` | 人物加坐椅，NE/SW 两朝向各两种外貌、共四格，真实 alpha | 桌子、屏幕、地板、墙面、角色/状态/任务文字 |

- 椅子只属于人物层；没有人物的桌边没有重复的空椅资产。不得把旧版“人物连同整桌”的素材当作新人物层。
- 最终人物图集实际为 **两朝向 × 每朝向两种外貌**，不是原计划的四朝向。NE 表示朝屏幕右上、背视；SW 表示朝屏幕左下、正视。当前资源未提供 SE/NW，代码不得把现有四格当四个不同朝向。
- 运行图为 1254×1254，按 2×2 分格，每格 627×627。已核对的顺序是：左上 0 男蓝衣/NE 背视；右上 1 女珊瑚衣/NE 背视；左下 2 女薄荷衣/SW 正视；右下 3 男芥黄衣/SW 正视。root、`office_design_audit` 和 `eight_role_protocol` 已通过截图检查姿态、原生尺度、完整轮廓及桌边适配。
- 两朝向共享人物比例、椅子尺度、视角和光向；外貌差异不得破坏座位对接。图集是朝向/外貌变体，不是四帧动画，也不代表四类岗位；岗位与执行状态由原生胶囊和真实 run 数据决定。
- 合成层次为房间 → 后排人物（z=2）→ 共享桌（z=3）→ 前排人物（z=4）→ 原生胶囊（z=7）。远侧座位 0/1 选择 SW 的格 2/3，近侧座位 2/3 选择 NE 的格 0/1；外貌由实例标识的稳定哈希决定。前后遮挡已实页查看通过，当前无需额外裁图或遮罩。
- 三桌岛共用同一模块；项目名、选择状态、交互热区和数量由代码绘制。图像内不得出现带示意人名、假进度或不可点击控件的整屏截图。

## 技术规格与来源

- 已用 Pillow 独立读取三张运行 WebP 的尺寸、模式、alpha 极值、实际字节并计算 SHA-256；完整哈希见 manifest。源稿目录、生成与编辑过程由资产负责人提供来源记录，未据此假称已检查原 PNG。

| 运行资产 | 实测像素 | 模式 / alpha 极值 | 编码字节 | RGBA8 解码估算 |
| --- | --- | --- | ---: | ---: |
| room | 1774×887 | RGB，不含 alpha | 165,894 B | 6,294,152 B |
| desk | 1536×1024 | RGBA，0–254 | 88,558 B | 6,291,456 B |
| people | 1254×1254 | RGBA，0–255 | 199,012 B | 6,290,064 B |
| 合计 | 三张运行图 | 桌与人物透明 | **453,464 B** | **18,875,672 B** |

- RGBA8 估算按每图宽 × 高 × 4 相加，约 18.00 MiB；这是统一格式的估算，不是浏览器实际内存测量。三张编码文件合计约 443 KiB，无新增运行依赖；此数值仅涵盖这三张资产。
- bundled `create-game-assets/scripts/asset_report.py` 对三图按实测尺寸执行检查，桌与人物额外启用 `--require-alpha`，三次均退出 0。报告在本机 `.local/office-v2-qa/studio-{room,desk,people}-v2-asset-report.json`。尺寸与 alpha 检查之外，构图、锚点、遮挡和透明边缘另由浏览器原生尺度审查覆盖。
- 资产负责人另报告用 Pillow `ImageChops.difference` 逐像素比较源 PNG 与 WebP 的 alpha：桌与人物的差异 bbox 均为 None，透明通道完全保留；此项由 root 执行，本任务未读取源稿重复验证。
- 房间为不透明场景图；桌与人物具有实测透明 alpha。半透明边缘、白边/黑边、椅子/头顶完整、格间分离及两朝向基线已由 root 和独立审查者在实页截图检查通过。原 PNG 的低 alpha 边缘噪点没有被直接当作裁切：`alpha > 0` 的 bbox 不能单独代表人物实轮廓。
- 当前按 CSS 放置背景与人物，不使用导入图片的像素 pivot：桌宽等于岛宽、上限 320 px，桌框比例 3:2；人物方框宽为岛宽的 35%，上限 112×112 px，transform-origin 为 50% 75%。桌面岛框比例 320:260，手机为 320:245；手机断点为视窗宽不超过 1023 px。完整座位坐标与图格定位已记入 manifest，并对照 `src/components/AgentOffice.tsx` / `agent-office.css` 核对。
- Web 使用 sRGB、平滑缩放；这是柔和卡通而非像素画，不强制 nearest。图片不平铺。图集按实测格框与统一坐姿/桌边锚点切分，缩放由同一场景尺度控制。
- 手机按所选项目展现桌岛，人物保持可读尺度；同一项目超过四人时增加桌岛而不丢 run。实际渲染已在下述断点与人数场景检查，浏览器内存没有另做实测。运行时复用同一套图片，不新增 3D 引擎、视频、外部角色库或运行时 AI。
- 统一概念参考：`exec-c0e61866-48dc-4dfc-816b-69f7c561967f.png`，已复制至 `docs/design/office-concept-v2.png`。概念与实页对照、原生尺度和图层集成已由 root 与独立审查者查看通过；可复用提示词在 [office-prompts.md](office-prompts.md)，原始精确工具调用保留于本任务历史。
- 三份源稿均由 root 在 2026-10-22 使用内置 ImageGen 生成：room 为 `exec-95ca61ae-be5c-4d71-913e-91066ef60f12.png`；desk 最终为 `exec-011c447c-c307-4bef-a7c2-58af6320c275.png`，从 `exec-466a8644-6457-478f-8564-338a126b9847.png` 精确编辑后排两台电脑为背向；people 为 `exec-06a7f33e-a27a-455d-bd06-3a4a116781ed.png`。源路径、编辑关系、导出参数与提示词入口均已记入 manifest。
- 来源为内置 ImageGen 生成输出，输入仅含本轮生成参考，无第三方输入资产或品牌。root 于 2026-10-22 核对了 [OpenAI 使用条款](https://openai.com/policies/terms-of-use/)：在用户与 OpenAI 之间，用户依适用法律拥有输出，输出可能并非独占。manifest 记录该条款来源，不套用 MIT/CC0 等第三方素材许可。
