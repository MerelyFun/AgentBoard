# 多执行办公室设计

2026-10-22，替代 V2 随执行数量不断增加桌岛的浏览方式。用户授权直接发布，并要求不影响已在开发的项目与 Agent。

## 信息与显示边界

- 全局项目、岗位、状态、关键词和活跃范围仍由 App 统一筛选。办公室内项目页签只选择当前要看的房间，不改变其他区域的全局结果。
- 办公室仅挂载当前项目的一页工位。桌面宽度 ≥1200 时每页 12 个执行，768–1199 时 8 个，手机 4 个；每桌四席，完整人物比例与桌前后遮挡保留。
- 场景高度固定，不随人数增加。页脚明确当前项目总执行数和显示范围，原生页码选择器可直达任何页，并提供首/前/后/末页。空数据不补假员工。
- 名单每页 20 个执行，内容区最高 480px、手机 440px，页码一直在内容区外。事件默认显示最近 5 条，展开为每页 10 条，仅统计本次收到的快照。
- 分页只截取显示数组。详情与身份仍使用完整快照，保留同实例的不同执行；不能按角色或实例去重。“个活跃执行”不声称是去重员工数。
- 筛选、来源或范围变化回第一页；数据减少时立即收敛至有效页，实时上报不无条件跳页。断点变化同步改变页容量和实际挂载数量。

## 视觉规范

参考 `scalable-office-concept.png`，内置 Image Gen 生成主屏概念（source `exec-f9ad47c8-00ed-4a84-b99d-04330dc3f76b.png`）。采用 `game-ui-ux` 的响应式、状态与键盘导航方法，以及 `frontend-app-builder` 的整页概念与浏览器核对流程。

- 白色 200px 侧栏、暖白 `#fafbf9` 画布、青绿 `#119d8f` 强调色，深色文字 `#25323c`。现有品牌与原生 Lucide 图标沿用。
- 主要标题 27px，区块标题 16–18px，常规操作 12–14px；分页按钮至少 36px，焦点描边清晰。
- 紧凑的项目阶段摘要和全局筛选在上，单个项目办公室为中间视觉焦点，执行名单和最近事件在下；避免三百张工位或长名单撑大页面。
- 三份 V2 房间、共享桌和坐姿人物 WebP 原样复用，合计 453,464 字节；没有新运行图片、依赖、字体或引擎。
- 房间画面由原图原色显示，无全图色罩；相同相机、光照和人物锚点。常驻标签只显示岗位与状态，完整任务、阶段和标识保留在原生详情。

概念的示例数字、任务和人物只是布局参考。生成图中虚构的项目负责人、完成比例与时间不进入产品；项目阶段继续读取真实上报。表格概念只画出部分可视行，实际为 20 条分页加有界滚动；原生页码支持首末直达。这些是数据真实性与多人可达性的约束，不将概念图当成真实项目进度。

## 验证与隔离

使用独立工作目录和本机 5175 端口，原仓库工作目录、角色安装、上报工具、数据库、令牌、访问码和游戏仓库不参与修改。30/100/300 执行只经浏览器本地导入测试；正式页只读检查登录、实时连接与退出。分页边界和全覆盖有独立单测。

浏览器插件在当前会话未提供，按测试技能使用已安装的 Playwright 与本机 Chrome。root 与独立评审已实际查看概念和满员截图，五项对照结果：

| 对照点 | 实际结果 |
| --- | --- |
| 项目聚焦 | 单个项目场景，页签显示真实过滤后数量，空项目可选 |
| 固定场景与工位上限 | 300 执行时仍为 430/390/340px，实际挂载 12/8/4 人，共享桌与前后遮挡保留 |
| 原生分页 | 桌面 25 页、手机 75 页逐页覆盖全部 300 执行，末页可直接打开详情并恢复焦点 |
| 名单与事件有界 | 名单 20 条/页且内部滚动；事件默认 5、展开 10 条/页，页脚不随内容滚走 |
| 桌面与手机布局 | 30/100/300 单项目及三项目六组通过；桌面页面高度保持 1617px，320px 手机无横向溢出 |

筛选回首页、同实例多执行、完整身份短 ID 碰撞、空态、300→3 页码收敛与减少动态通过。浏览器控制台/页面错误及六组测试外部请求均为 0。证据在当前 Codex 任务目录 `artifacts/crowd-independent/`，不提交可能包含运行信息的截图；新概念图只含示例数据。
